Lesson 1 · The learning loop

Where a rule lives decides whether it survives

Your vault holds one instruction that the model may quietly skip, and one it cannot. They differ by a single line of JSON. Knowing which is which is the whole of decision 1.

The two sentences

Both of these are in your repo right now. Only one of them is enforced.

Their profile is a note: cortex/03_Resources/About me.md. Read it at the start of every session. AGENTS.md:23
brain/bin/agreement extracts just those three sections and UserPromptSubmit re-states them before every prompt. AGENTS.md:87

The first is a request to a model. It is obeyed when the model is attentive, the session is short, and nothing more urgent is competing. The second is a guarantee from the harness: a process runs, its output is prepended, and no amount of model inattention can skip it. Your vault already made this exact argument for style, and then never applied it to identity.

Three channels, and only three

Claude Code fires 31 hook events. Exactly three of them can put text where the model will read it: SessionStart, UserPromptSubmit and UserPromptExpansion. For every other event, standard output goes to a debug log the model never sees.* That constraint, not preference, is what shapes the design.

You already wrote the budget down

[[About me]] is capped at 40 lines. [[How we work together]] is capped at 15. brain/bin/doctor enforces both. The reason given for the tighter cap is the interesting part:

The hub is paid for once a session; this is paid for on every prompt, which makes it the most expensive file in the vault per line. AGENTS.md:112

That is a per-session budget and a per-turn budget, named and sized. The per-turn channel is wired to brain/bin/agreement. The per-session channel is sized, justified, and connected to nothing. Decision 1 is not "should we add a hook". It is "should we finally use the slot the manual already budgeted for".

A wrinkle worth catching

AGENTS.md:48 says the hub is "paid for on every turn". AGENTS.md:112 says it is "paid for once a session". Both are defensible, because paid means two things: how often a file is read, and how often its tokens are re-sent. A note read at session start is read once and then carried in context. A hook firing every prompt appends new tokens every turn. If you tighten one sentence in the manual this week, make it that one, because it is the sentence the SessionStart payload gets sized against.

The compaction trap

SessionStart takes a matcher on how the session began: startup, resume, clear, compact, fork.* The instinct is to fire only on startup and save the tokens. That instinct is backwards for one value.

  • resume and fork: the earlier injection is still in the transcript. Re-firing is waste.
  • startup and clear: nothing is there yet. Fire.
  • compact: the context was just summarised, and a 40-line profile is exactly the kind of thing a summariser flattens into "the user has a profile". This is the moment the vault most needs re-stating, not least.

Compaction is where a long session quietly stops knowing who it is talking to. A hook that skips it optimises the cheap case and abandons the expensive one.

The line you cannot cross

The note is the source of truth and the hook is a convenience over it; never move a preference into .claude/, where three-quarters of the agents that read this manual will never see it. AGENTS.md:88

A hook may only re-state what a note already holds. The moment a hook becomes the only place a fact lives, the vault stops being portable and your agnostic pitch stops being true. This is why the design is brain/bin/context reading cortex/, and never a block of profile text pasted into settings.json.

House style for a hook here

brain/bin/agreement already documents the rules in its own comments. Any new hook copies them:

# Never exit non-zero, never write to stderr. A hook that fails puts a
# "hook error" notice in front of the human on every keypress.
root=$(cd "$(dirname "$0")/../.." 2>/dev/null && pwd -P) || exit 0
[ -f "$root/AGENTS.md" ] && [ -d "$root/brain/bin" ] || exit 0

Anchor to the script, not the working directory. Prove you are in a vault. POSIX shell and awk, no runtime. Label the output so injected text never reads as something the human just said. Cap the bytes. Read the note fresh every time, so an edit takes effect on the next prompt.

Before you close this

A colleague proposes putting the working agreement in SessionStart instead of UserPromptSubmit, to save tokens. Give the one-sentence reason that is wrong, and the one case where they have a point.

Check yourself

Wrong because the agreement exists to beat decay: a style rule stated once at turn 1 loses to everything said by turn 40, which is the failure AGENTS.md:82 names. Moving it to session start recreates exactly the problem the hook was built to solve.

They have a point about the profile, not the agreement. Identity is stable and expensive; style is cheap and perishable. Stable facts belong in the once-per-session channel, perishable contracts in the per-turn one. That split is the answer to decision 1.
